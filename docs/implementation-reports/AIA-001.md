# AIA-001 — reporte de implementación y auditoría local

Fecha: 2026-08-29. Riesgo: R3. Worktree: `/private/tmp/kiwi-admin-ai-assistant`.

## Resultado

Quedó implementado el primer vertical gobernado del asistente exclusivo de Admin: consulta de un
corpus canónico citado y propuestas de una sola acción para crear/actualizar producto, crear insumo,
crear grupo/opción de modificador y versionar receta. El icono `UserRound` sustituye el botón
decorativo del encabezado, sin sustituir el avatar de perfil. La revisión se abre sobre la ruta de
configuración y compara actual vs propuesto antes de aceptar o rechazar.

El proveedor no tiene herramientas de escritura. Su salida estricta se trata como no confiable: el
backend verifica fuente, evidencia cita↔valor, identificación del objetivo, referencias de unidad e
insumo, organización, estado, permiso, expiración, fingerprint e idempotencia. Sólo después delega a
los servicios canónicos. Prompt, transcript y secreto no se persisten ni se registran en auditoría.

## Hallazgos de auditoría corregidos

1. La entrega inicial de Terra era parcial: faltaban PRD/SDD/BDD/TDD/matriz completos, aplicación
   canónica, frontera HTTP y pruebas de lifecycle/migración.
2. La primera validación sólo comprobaba que una cita existiera; ahora exige que respalde el valor y
   el registro objetivo, y que unidades/insumos referenciados estén identificados por el usuario.
3. Se rechazaron tipos JSON ambiguos para enteros/booleanos y precios no positivos.
4. Las referencias sembradas de Orders e Inventory apuntaban a secciones SDD incorrectas; fueron
   corregidas a `SDD §5.4` y `SDD §5.7`, y el corpus se amplió a los dominios principales.
5. La comparación de receta no incluía componentes actuales; ahora los incluye.
6. Se añadió prueba de producto nuevo, actor no autorizado, expiración, mismatch cita↔valor,
   replay, stale, rechazo, las cinco familias de acción, HTTP default-off y downgrade con historia.
